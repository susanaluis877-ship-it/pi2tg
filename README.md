# pi2tg

通过 Telegram 私聊控制和查看**当前终端中的 Pi 会话**。单用户、文本优先，支持 Markdown 回复渲染。

## 环境

- Node.js 22 或更高版本。
- 当前针对 `@earendil-works/pi-coding-agent` **1.5.0** 的扩展 API 开发并进行类型检查。使用 `turn_end` 可操作边界及 `agent_settled`，不保证旧版本兼容。
- 本机必须能访问 `https://api.telegram.org`。
- 一个专用 Bot Token 同时只运行一个实例；不要与 webhook 服务或其他轮询程序共用。

## 安装

发布 npm 后可安装：

```bash
pi install npm:@susanaluis877/pi2tg
```

或从 GitHub 安装：

```bash
pi install git:github.com/susanaluis877-ship-it/pi2tg
```

在目标项目目录创建 `.pi/pi2tg.env`（不要提交到 Git）：

```dotenv
PI2TG_BOT_TOKEN=你的BotToken
PI2TG_USER_ID=你的数字Telegram用户ID
```

执行 `chmod 600 .pi/pi2tg.env`，将 `.pi/pi2tg.env` 加入该项目 `.gitignore`。启动 Pi、信任项目，或在已有受信任会话中执行 `/reload`。首次使用请先在 Telegram 私聊 Bot 并点击 Start。

**安全提醒：此插件允许白名单用户远程指挥本地 agent，权限与 Pi 相同。终端任务的回复也会外发到 Telegram；敏感项目请勿启用。**

## 快速开始

1. 向 Telegram 的 **@BotFather** 发送 `/newbot` 创建 Bot。
2. 获取自己的数字 Telegram 用户 ID（不是用户名，也不是 Bot ID）。请通过可信方式获取，并核实 ID。
3. **先在 Telegram 私聊你的 Bot 并点击 Start**，否则 Bot 无法主动给你发送消息。
4. 在 **Pi 会话工作目录**创建 `.pi/pi2tg.env`，参考插件的 `.env.example` 填入 Token 和用户 ID。每个项目使用自己的 Bot，无需 source。

```bash
mkdir -p .pi
cp /absolute/path/to/pi2tg/.env.example .pi/pi2tg.env
chmod 600 .pi/pi2tg.env
# 用编辑器填入真实凭据，并将 .pi/pi2tg.env 加入项目 .gitignore
pi -e /absolute/path/to/pi2tg/src/index.ts
```

长期安装：

```bash
pi install /absolute/path/to/pi2tg
# 此后启动 pi，或在已有会话里 /reload
```

只在 `session_start` 读取受信任项目的 `<ctx.cwd>/.pi/pi2tg.env`。无配置或项目未受信任则不连接；不回退到插件目录 `.env`，也不读取 shell 中的 PI2TG 凭据，避免跨项目误绑定。文件仅按 dotenv 解析，不执行 shell 或展开变量。

agent 执行 `cd`、指定工具工作目录、访问其他目录的文件，均不会更改绑定。仅显式切换 Pi 会话（按目标会话 cwd）或 `/reload` 时重新读取配置。连接通知显示项目名和会话 ID。

同一用户的本机实例通过 `~/.pi/pi2tg-locks` 互斥锁保护同一 Bot，锁标识使用 Bot ID 哈希，不存 Token。每 10 秒心跳，异常退出后最多约 2 分钟可恢复；锁失效则关闭连接。不能防止其他系统用户或其他机器抢占同一个 Bot。正常重载/退出先关闭连接再释放锁。

从旧版迁移：将原插件目录 `.env` 移到当前项目 `.pi/pi2tg.env`，设置权限 600 并添加 Git 忽略，然后 `/reload`。配置错误或联网失败会在终端提示。不要提交真实凭据。

## 使用

| Telegram 输入 | 行为 |
|---|---|
| 普通文本 | 空闲时提交，忙碌时进入插件 FIFO 待办队列 |
| `/steer 补充要求` | 当前轮工具执行结束后加入上下文；空闲时作为新任务 |
| `/status` | 查看执行/等待/停止状态、待办数、工具调用数和耗时 |
| `/models` | 列出 Pi 当前配置及认证允许使用的模型，标记图片能力 |
| `/model` | 查看当前会话模型 |
| `/model provider/model-id` | 空闲且无下载/待办时切换当前会话模型，也支持唯一模型 ID |
| `/stop` | 清空未投递 Telegram 消息，并请求取消当前执行 |
| `/help`、`/start` | 显示帮助 |
| `/reload` | 取消尚未投递的 Telegram 消息，在 Pi 空闲后重新加载全部资源 |

终端发起的任务也会推送。通知包括单条动态执行面板，以及独立发送的不含工具调用的完整 assistant 回复。不是逐 token 转发；模型中途产生的纯文本回复也可能被转发，不应把每条回复都视作整个任务结束。

Agent 回复由 `marked` 解析 Markdown，再转换为 Telegram 原生消息 entities：标题显示为粗体，支持粗体、斜体、删除线、行内代码、代码块、链接和列表；表格使用等宽文本展示。原始 HTML 保留为字面文本，不执行也不作为 Telegram HTML 解析。状态通知保持纯文本。

长结果按 UTF-16 保守长度切分，不拆开 emoji 代理对，跨段格式同步裁剪。链接预览关闭。格式被 Telegram 拒绝时自动退回无格式文本，优先确保结果送达。

模型切换使用 Pi 官方 `pi.setModel()`，不改写 CC Switch 配置，也不改变全局默认模型。图片支持标记来自配置声明，并不保证转发服务实际支持视觉。`/models` 使用 Pi 当前已加载的模型注册表，不主动刷新 CC Switch 外部配置。执行、下载、待办、等待确认或重载期间拒绝切换，避免改变正在处理任务的模型。

## 命令菜单与按钮

连接时为白名单用户的私聊注册 Telegram 命令菜单。连接通知及 `/help` 带有“状态、模型、停止、重载”按钮；`/models` 显示可点击的模型列表（最多 40 个，其他模型仍可用文本命令切换）。

停止与重载按钮需要二次确认；直接输入 `/stop`、`/reload` 保持原有立即接收语义。模型按钮复用原有模型切换状态检查。

按钮每组仅可使用一次，有效期 15 分钟，点击取消也会使同组确认失效。执行开始/结束后，旧停止、重载和模型按钮失效；重载后所有旧按钮失效。发送 `/help` 或 `/models` 获取新按钮。回调重新检查用户 ID 和私聊 ID，不把按钮内容交给模型；长模型 ID 通过内存短 token 映射，不受 callback_data 的 64 字节限制。

菜单注册失败只在终端提醒，不影响文本命令或 Bot 连接。

## 动态执行面板

每次从空闲开始的执行创建一条面板，后续编辑同一消息，而不是逐条发送工具通知。展示任务输入的前 100 个字符、当前工具及耗时、并行工具数、读取/修改/命令等统计、工具失败次数、最近 3 条活动和 Telegram 待办数。

- 普通工具事件合并更新，最多每 4 秒刷新一次；没有新事件时每 15 秒更新耗时。
- 等待终端确认、停止、准备重载、执行结束优先请求刷新；实际发送仍与其他消息共享串行队列及限流。
- 展示相对文件路径，项目外路径隐藏；仅显示少量允许的常见命令前缀，不发送完整命令参数、工具输出或内部思考。任务摘要及项目内路径仍可能含敏感信息，请勿在敏感任务启用外发。
- 并行时显示工具数量和前两个活动工具；最近记录滚动保留三条。
- 面板仅保留最新待发送快照，避免网络恢复后重播过期进度。永久编辑失败后禁用该面板并在终端提示，避免重复创建消息刷屏；仍可 `/status` 查询。
- 最终面板显示“执行已结束”或“已中止”，不表示所有业务需求都成功。模型错误和工具失败会被记录，但 agent 可能自行恢复。
- `/status` 提供即时快照，并额外显示当前模型、图片下载数、插话数和待重载状态。
- 重载/退出会停止刷新并关闭网络连接；尚未送达的更新可能丢失。

## 图片输入

支持直接发送 Telegram 照片/截图，或以文件形式发送 PNG、JPEG、WebP、GIF。图片说明（caption）会和图片一起交给当前模型；没有说明时使用默认的查看图片提示。建议把问题写在图片说明中，不要分开发送，因为下载期间收到的文本可能先执行。

- 单张最大 10 MiB；检查声明大小、实际下载大小和文件签名。不支持 SVG、PDF、视频或贴纸；GIF 的动画理解能力取决于模型。
- 必须选择支持 image 输入的模型，接收和实际提交时均检查模型能力。
- 最多并行下载 3 张，最多保留 5 张已下载待办；按下载完成顺序入队，相册按独立图片处理，不自动合并。
- 图片按普通任务排队，暂不支持图片 `/steer`。以 `/` 开头的图片说明会被拒绝，控制命令请单独发送。
- `/stop`、中止事件、重载和退出会取消未完成下载，防止停止后图片继续提交。
- 下载仅在白名单鉴权后进行，使用 HTTPS Telegram 文件接口，不记录 Token 或文件下载地址。插件不主动保存图片文件，但图片会进入 Pi 会话与模型请求，Pi 自身可能持久化会话内容。
- 此处描述入站图片。出站文件和图片由 `telegram_send_file` 工具显式发送，见下一节。

## 主动提问与交付物回传

本地加载后，agent 可调用两个新工具（不是 Telegram slash 命令）：

### `telegram_ask`

用于需求澄清，例如让 agent 询问你希望采用的方案。支持最多 8 个单选按钮，或使用 Telegram 的「回复」功能回复原问题消息输入自由文本。普通未关联的消息仍是新任务，不会被误当答案。每次仅允许一个待回答问题。

默认超时 **5 分钟（300 秒）**，可设置 30–900 秒（包括排队发送时间）。超时不选择默认答案，工具返回 timeout 并请求结束当前执行。原问题保留选项，可在同一会话 24 小时内点击或回复原消息补答；补答将原问题与答案作为新的继续任务指令提交，忙碌时排队，不复活旧工具调用。单独发送 A/B 不会自动关联问题。

回答后尝试编辑原消息并移除按钮，即使编辑失败也只接收一次答案。最多保留 20 个超时问题，超出时清理最早记录。已取消或发送失败的问题不接受补答；`/stop`、`/reload`、中止、会话关闭、实例锁失效会清除全部补答记录。记录仅存内存，不跨重载/会话恢复。所有回答仍不代表权限批准。

**这不是权限审批机制。** 普通需求回答不授权危险命令，也不接管任何终端权限确认。等待时执行面板和 `/status` 显示等待 Telegram 回复。

### `telegram_send_file`

用户可以要求 agent 回传报告、patch、PDF 或截图。`path` 指向当前受信任项目内的文件，`caption` 为可选说明。默认作为可下载的文档发送；`photo: true` 可将 PNG/JPEG 作为预览图片发送，Telegram 可能压缩预览，保留原始质量请用文档方式。此工具只上传已有文件，不负责生成截图。

- 文件必须非空且 ≤10 MiB，拒绝目录、符号链接路径、硬链接和项目外路径。
- 拒绝 `.env*`、`*.env`、`.git`、`.ssh`、`.aws`、私钥扩展名以及常见 credentials/secrets 文件名。
- 工具只应发送用户要求或当前任务直接相关的成果；不自动批量上传项目。
- 与通知共用发送队列，支持取消和关闭清理。成功结果含 Telegram 消息 ID；网络响应丢失可能已送达，不盲目重试上传。429 限流最多重试两次。
- 文件检查是降低误传风险，不是隔离沙箱，也不检测所有秘密内容。恶意进程并发修改文件/目录仍有竞态风险；普通命名的文件、报告和截图也可能含秘密，发送前应检查。插件与 Pi 拥有相同系统权限。

验收示例：

1. 发「请用 telegram_ask 问我选择 A 还是 B，然后告诉我选择结果」。
2. 点击选项，确认 agent 恢复执行；另测用「回复」原问题输入自定义答案。
3. 在等待问题时发 `/stop`，确认旧按钮失效且不会按默认答案继续。
4. 发「创建一个无敏感信息的测试报告，并用 telegram_send_file 发给我」。
5. 发「将项目内已有的测试 PNG 作为图片预览发给我」，检查图片显示。

目前提供单元和模拟传输测试，真实提问、回复和上传链路仍需手动验收。交付后的快捷操作按钮暂未加入。

## 热加载

修改代码或 `.pi/pi2tg.env` 后，可在 Pi 终端或 Telegram 私聊发送 `/reload`。第一次加载本功能仍需在 Pi 终端执行 `/reload`。

Telegram 命令通过注册的 `/pi2tg-reload` 扩展命令调用 `ExtensionCommandContext.reload()`，不发送给模型。若正在执行或等待终端确认，会等待 Pi 空闲，不强制中止；必要时可先 `/stop`。请求重载时取消未投递的 Telegram 待办和插话，并暂时拒收新任务；不会清空终端原生待办。

重载保留当前会话历史，但重置插件内存、重新读取 `.pi/pi2tg.env` 并重建 Bot 连接。它重载的是 Pi 全部资源，不仅此插件。等待新的“Pi 会话已连接”通知后再发送任务。旧发送队列会被关闭，因此重载请求确认消息可能来不及送达。

如果新代码存在加载错误，或新配置导致无法联网/鉴权失败，Telegram 无法远程修复；请在终端检查并 `/reload`。

## 排队与停止语义

Pi 扩展 API 没有公开的按来源删除原生待办接口，因此：

- 普通 Telegram 待办保存在插件内存中，Pi 完全空闲且没有原生待办时才逐条提交。
- 插话在 `turn_end` 安全边界作为标记为 `pi2tg-steer` 的用户角色上下文消息加入，要求下一轮继续。它不是原生 `sendUserMessage` steering，因此不会经过普通输入转换钩子、技能或模板展开。
- `/stop` 清空尚未投递的插件任务和插话，再调用 Pi 的 `ctx.abort()`。**不调用 Pi 的全局队列清空方法**。终端待办仍遵循 Pi 自身取消语义。
- 已投递到上下文的插话不能撤销；已完成的文件修改不会回滚。正在执行的工具是否及时停止取决于取消支持。
- 终端中止同样会清空尚未投递的 Telegram 待办，避免中止后自动开工。
- 晚于最后一个 turn 边界收到的插话，会在完全空闲后作为后续任务处理。
- 最多保存 50 条未投递消息。停止中或队列已满时拒收，并提示重发。
- 一切仍在同一会话中执行，不提供独立任务工作区或任务完成保证。

## 生命周期、网络与安全

- 仅接受配置用户本人在其私聊中发送的消息；其他用户和群聊被静默忽略。
- `/new`、`/resume`、`/fork`、`/reload`、退出会关闭旧 Bot 连接。待办不持久化，不跨会话恢复。
- **每次连接时跳过全部离线积压消息**，包括首次启动和 reload。请等待“Pi 会话已连接”通知后再发送任务。
- 在线期间按 `update_id` 去重；单次处理失败不会自动重放指令。这不是崩溃恢复或事务式 exactly-once 保证。
- 收发独立，不等待 agent 完成，也不让 Telegram 网络请求阻塞流式事件。网络错误退避重试，发送限速，429 遵循 retry_after。
- 发送最多尝试 5 次；发送队列最多 500 段，溢出或失败会在终端提醒。进程退出会丢弃尚未发出的通知。网络响应丢失后重试可能造成重复通知。
- 发现 webhook 不会主动删除；401/403/409 接收错误会停止轮询并提示检查配置或重复实例，然后 `/reload`。
- 本版本仅在 Pi 的 TUI 模式启动，不作为独立 daemon 工作。机器休眠、Pi 退出时无法及时接收指令。
- 不绕过权限插件。出现终端确认窗口时只发提醒，必须在终端确认；Telegram 文本不代表批准。
- 不发送思考内容、工具参数或原始工具输出。**最终回复仍可能包含代码和秘密，且会离开本机进入 Telegram；不提供自动秘密过滤。** 对敏感项目请不要启用插件。
- Bot Token 是远程控制凭据；泄露后立即通过 BotFather 撤销。插件运行权限与 Pi 相同，不提供额外沙箱。

## 开发与测试

```bash
npm install
npm run typecheck
npm test
```

文件结构：

```text
src/index.ts           Pi 生命周期、事件与 Telegram 命令路由
src/core.ts            配置校验、鉴权、消息分段和待办队列
src/config.ts          受信任会话目录配置读取
src/lock.ts            本机 Bot 实例互斥锁
src/telegram.ts        Telegram Bot API、长轮询、发送队列与重试
 test/core.test.ts      核心逻辑测试
 test/extension.test.ts 模拟 Pi 和 Telegram 的集成测试
```

运行时使用 Node 内置 API、`marked` Markdown 解析器和 `proper-lockfile` 实例锁；Pi 类型包仅用于开发检查。新增依赖后，本地路径安装的用户需在插件目录执行 `npm install`。

### 真实 Bot 手动验收

自动化测试使用模拟接口，不能替代以下真实联调：

1. 启动 Pi，确认 Telegram 收到连接通知，`/status` 返回空闲。
2. Telegram 发送“只回复 hello”，确认当前终端显示执行且 Bot 收到回复。
3. 从终端发起任务，确认 Telegram 同样收到进度和回复。
4. 执行耗时任务时发送第二条任务，确认它在当前工作结束后执行。
5. 执行中发送 `/steer 不要修改文件，只分析`，确认下一轮上下文出现补充；不要用它阻止已在执行的危险操作。
6. 执行中追加任务和插话，发送 `/stop`，确认中止后不再执行未投递任务；再次发新任务仍可执行。
7. 用其他账号或群聊发指令，确认无响应且没有执行。
